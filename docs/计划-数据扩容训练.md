# 计划 · 训练数据扩容（多视频）重训 ft

> ⚠️ **已暂缓（2026-08-24）**：诊断证明摇杆相关低是"学不会"（训练集 +0.042 与测试集同量级），扩数据对摇杆无效。当前方向已改为 **摇杆加权 loss**，见 `docs/计划-摇杆加权重训.md`。本文保留作备用（若日后要提升按键泛化）。

> 2026-08-24 制定 · 目标：扩训练数据提升 LoRA 微调泛化，冲击摇杆相关系数 ≥0.4（当前 +0.126，唯一未达标指标）

---

## 0. 背景与目标

现状：训练只用 1 个视频（`Z1r1S--MJS4`，前 640s / 38400 帧），LoRA 行为克隆容易过拟合单视频的风格/地图/玩家。经扫描 `SHARD_0088.tar`，该分片内共有 **12 个 rocket_league 视频（全部带 actions_processed）**，无需下载新分片。

**目标**：扩训练数据到多个中小时长 youtube 视频，提升泛化，冲击摇杆相关 ≥0.4。

**选择理由**：
- youtube 源（yt-dlp 下载稳定，与 Z1r1S--MJS4 同方式）
- 5 个不同玩家/地图 → 数据多样性好，这是行为克隆泛化的关键
- **不用** twitch 源 5 个（VOD 下载可能受限）
- **暂缓** QyH30FEdOXg（89 分钟单视频）：单一主播风格，过拟合风险高、下载体积大——先小步验证，效果好再加

## 2. 下载规格（用户执行）

- **分辨率：1080p**（原始为 1080×1920 竖屏；抽帧会 scale=256:256，1080p 保留信息最多）
- 格式：`.mp4`
- 命名：`<video_id>.mp4`（如 `CryOgQGVpyw.mp4`）
- 存放：`D:\2+课产品\_data\videos\`
- 命令模板（每条视频一条）：
  ```
  yt-dlp -f "bv*[height<=1080]+ba/b[height<=1080]" -o "D:\2+课产品\_data\videos\CryOgQGVpyw.mp4" "https://www.youtube.com/watch?v=CryOgQGVpyw"
  ```
  若之前下载 Z1r1S--MJS4 视频用了 `cookies.txt` 或特殊参数，沿用同样方式。

## 3. 实施步骤（依赖顺序）

| # | 任务 | 谁做 | 说明 |
|---|------|------|------|
| 1 | 从 `SHARD_0088.tar` 解压 5 个视频的 parquet+metadata 到 `_data/SHARD_0088/<video_id>/` | 助手 | 只解压目标视频，秒级 |
| 2 | 下载 5 个视频 mp4 到 `_data/videos/` | **用户** | 见 §2 |
| 3 | 改造 `train/data_pipeline.py` 多视频化 | 助手 | 缓存键带 video_id；抽帧范围按各视频实际 chunks；训练采样按视频分组 |
| 4 | 抽帧 + 动作缓存（每视频独立，后台） | 助手 | 总计约 27.7 万帧，注意磁盘空间 |
| 5 | 训练 | 助手 | 第一批先加 3 个视频跑一版（~18.6 万帧）验证，效果好补另 2 个 |
| 6 | 评测对比 | 助手 | **评测仍用 Z1r1S--MJS4 的 chunk 32~34**（保持与 baseline/旧 ft 可比），新视频只进训练 |
| 7 | 收尾 | 助手 | 更新 `train/RESULTS.md` / 项目备忘 / 差距清单 |

## 4. 验收（Given-When-Then）

- **给定**：5 个视频 mp4 就位 + parquet 已解压 + 管线改造完成；
- **当**：重训 ft 并用 Z1r1S--MJS4 测试集（chunk 32~34，200 帧等间隔）评测；
- **则**：按键准确率/召回率不显著回退（≥旧 ft 的 90%）；摇杆相关系数 ≥0.126 且呈提升趋势（目标 ≥0.4）；结果如实记录到 `train/RESULTS.md`。

## 5. 风险与回退

| 风险 | 应对 |
|------|------|
| 个别视频下载失败/不可用 | 跳过该视频，用其余 4 个 |
| 抽帧量大耗时 | 后台跑；期间准备"摇杆加权 loss"备选方案 |
| 训练过拟合（验证 loss 回升） | 监控验证集，早停或降低步数 |
| 指标不提升 | 如实呈现；回到摇杆加权 loss 方向（G3） |

# NitroGen 评测工作台 — Web 演示说明（详细复现版）

> 目标：让**另一台机器上的 AI 或人类**仅凭本说明，从零复现整套 Web 演示。
> 对应代码仓库：`GeneralGameAgent-Web/`（本项目）。
> 本文档按"环境 → 启动 → 逐功能演示 → API → 排障"顺序编写，所有命令均可直接复制执行。

---

## 0. 这是什么

一套 **Vue3 + Vite + ECharts 前端 / FastAPI 后端** 的 Web 工具，用于展示一个《火箭联盟》游戏智能体（NitroGen）**LoRA 微调前后**的行为差异，并支持**在线推理**：

- **查看器（首页）**：M4 指标卡、逐帧曲线、微调前后对比表、分段曲线与演示条
- **在线推理**：单帧推理、批量评测（200 帧）、把评测结果保存为 ft 结果集、动态推理曲线
- **素材评测工作台**：上传自己的视频 + 动作标注 → 拆帧 → 选帧跑智能体对比

**核心结论（如实呈现）**：LoRA 微调后按键召回率提升约 15 倍、F1 提升约 8 倍（基准 88.3% → 91.3% 准确率）；但摇杆相关性未达目标 0.4，页面如实标注"未达标"，不修饰。

## 4. 功能演示脚本（逐步操作 + 预期结果）

### 4.1 查看器（默认首页）

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 打开首页，看顶部指标条 | 6 张指标卡：按键准确率 / 触发召回率 / 触发精确率 / F1 / 摇杆相关 / 摇杆 MSE。**默认显示「调优前 baseline」**：准确率约 **88.3%**、召回 4.2%、F1 0.079、摇杆相关 0.063（未达标红色徽标） |
| 2 | 右上角"重新加载" | 数据刷新，更新时间更新 |
| 3 | 顶栏右侧版本下拉框切到「ft · 调优后」 | 指标卡变为 **91.3%** 准确率、召回 65.3%、F1 0.643、摇杆相关 0.083；段图区出现虚线提示"该版本暂无分段曲线"（ft 段图未生成） |
| 4 | 切回「baseline · 调优前」 | 段图恢复；左侧"调优前 baseline"段图 + Top5 差异帧表 |
| 5 | 查看三张曲线图（下方区域） | ① 总览图：200 帧逐帧 j_left MSE + 按键准确率；② 摇杆叠加图：gt 人类 / baseline / ft 三条线（越贴近 gt 越准）；③ 分段柱状图：当前段 Top5 差异帧 |
| 6 | 段选择下拉框切换（60s–80s … 660s–680s） | 左侧段图、Top5 表、底部演示条同步变化 |
| 7 | 底部演示条 | 60s–80s 段显示 5 个演示帧（gt/pred 按键对比）；其它段显示 Top5 差异帧编号 |
| 8 | 指标条下方"微调前后对比"表 | baseline vs ft 六项指标 + 差值 + 判定（提升/变差/达标/未达标） |

**数据流**：`/api/metrics?version=`（指标）· `/api/frames?version=`（总览曲线）· `/api/segments?version=`（段）· `/api/comparison`（叠加曲线）· `/api/demo?version=`（演示帧）· `/api/figures/curves/<file>.png`（段图静态图）。

### 4.2 在线推理（顶部导航切到「在线推理」）

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | 顶部出现"推理模型"选择条 | 默认「调优后（LoRA ft · 准确率更高）」。**首次推理会加载约 2GB 的 ft_lora.pt，耗时约 1 分钟**（页面提示"切换模型后首次推理会重新加载"） |
| 2 | 单帧推理：输入帧号 `38400`（=t=640s），点"开始推理" | 显示推理耗时；gt/pred 按键对比；摇杆 MSE。**ft 模型通常能识别出按键**（如 dpad_down/dpad_left/right_trigger），baseline 常为"无" |
| 3 | 批量评测：点"运行批量评测" | 评测 200 帧（测试集 640–700s，K=3 多数票），**约 5–6 分钟**。完成后显示：准确率（**ft 约 91%**）/召回/摇杆相关 |
| 4 | 点"保存为 ft 结果" | **瞬间完成**（不再重跑）；自动切到 ft 版本，首页指标卡/总览曲线更新为刚保存的结果 |
| 5 | 拉到底部"推理曲线"卡片 | 显示本次操作结果的 gt/pred 摇杆曲线：单帧=1 个点、批量=200 帧连成的完整曲线；坐标固定（x=时间秒，y=j_left −1~1） |
| 6 | 推理模型切到「调优前 baseline」再跑单帧 | 单帧推理输出与 ft 明显不同（按键少）；推理曲线同步更新 |
| 7 | 换帧号推理（如 `38640`=t=644s） | 推理曲线新增对应时间点 |

**关键点**：Web 评测用哪个模型由"推理模型"选择条决定——**调优后结果必须选「ft」再跑批量评测**，否则测的是 baseline（约 88%）。

### 4.3 素材评测工作台（在线推理页最下方）

前置：准备一段自己的游戏视频 + 与 NitroGen 同构的动作标注（parquet，列含 17 键按钮 + j_left 等）。

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | "新建"素材（输入名称） | 素材出现在下拉框（0 帧） |
| 2 | 选中素材后：上传视频 / 上传标注（文件夹找 `actions_processed.parquet` 或单文件） | 显示"视频✓ 标注✓"；标注覆盖行数提示 |
| 3 | 设置起/止秒 + 拆帧密度（1~60fps），点"拆帧" | 帧网格出现，每格一张帧图 + 编号 |
| 4 | 点选帧（可多选），或"按区间选"（如 `1~10`） | 帧高亮（青色边框） |
| 5 | 点"推理选中 N 帧" | 每帧一张推理结果卡（gt/pred 按键 chip + 按键一致数 + 摇杆 MSE） |
| 6 | 点"批量对比" | 逐帧聚合对比（按下状态 + 一致数） |
| 7 | 推理后看底部"推理曲线" | 曲线变为该素材选中帧的 gt/pred 摇杆曲线（**数据随所选帧/素材变化，坐标固定**） |

## 5. 后端 API 速查

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/health` | 健康检查 + 结果集版本列表 |
| GET | `/api/results` | 结果集列表（baseline / ft + 标签） |
| GET | `/api/metrics?version=` | 某版本六指标 + M4 判定 |
| GET | `/api/segments?version=` | 21 段曲线（top5 差异帧 + 图文件名） |
| GET | `/api/frames?version=&limit=&offset=` | 逐帧明细（总览曲线数据） |
| GET | `/api/comparison` | 叠加曲线数据（gt / baseline / ft 三线） |
| GET | `/api/demo?version=` | M5 演示帧对比 |
| GET | `/api/figures/<name>` | 静态 PNG（含 `curves/` 子目录） |
| POST | `/api/predict` | 单帧推理（body: `{fid, k, asset_id, sec, model}`） |
| POST | `/api/evaluate` | 批量评测（body: `{n, k, save, label, asset_id, fids, result, model}`） |
| GET | `/api/infer/status` | 模型加载状态（`loaded` + `model`） |
| POST | `/api/assets` 等 | 素材工作台（新建/上传视频/上传标注/拆帧/删素材） |

**`model` 取值**：`baseline`（ng.pt 调优前）| `ft`（ft_lora.pt 调优后）。未传默认 `baseline`。

## 6. 已知边界与注意事项

1. **ft 段图为空**：`ft.json` 只含指标与逐帧数据，段图/演示条仅 baseline 生成。ft 版本下段图区显示提示，切回 baseline 可看。
2. **摇杆相关未达标**：LoRA 微调后摇杆相关约 0.083，未达 M4 目标 0.4，页面如实标注"未达标"，这是当前模型的真实能力，非 bug。
3. **批量评测耗时**：200 帧 K=3 约 5–6 分钟；期间页面按钮禁用（全局互斥），请勿重复点击。
4. **显存**：两套模型共约 9GB，**同一时刻只驻留一个**；切换模型时后端自动释放旧模型再加载新模型（约几秒到 1 分钟）。
5. **离线 HuggingFace**：后端已设 `HF_HUB_OFFLINE=1`，模型加载走本地缓存，不会因联网失败卡死。
6. **临时文件**：抽帧临时 PNG 使用唯一文件名写入 `backend/data/_tmp_frames/`，推理完自动删除；该目录不入 git。

## 7. 排障（FAQ）

| 现象 | 原因 | 处理 |
|------|------|------|
| 页面右上角"API 离线" | 后端 8000 没起来 | 按第 3 节启动后端；`curl http://127.0.0.1:8000/api/health` 应返回 ok |
| 前端 500 / 数据加载失败 | 后端未启动 | 先启后端再刷新页面 |
| 推理很慢（1 分钟+） | 首次加载模型 | 正常；之后切换模型复用，秒级 |
| "模型文件不存在" | `ft_lora.pt` 未训练/未放到位 | 跑 `train/train_lora.py` 生成，或确认 `train/ckpt/ft_lora.pt` 存在 |
| "抽帧失败" | ffmpeg 不在 PATH 或视频路径错误 | 确认 ffmpeg 可用；检查视频路径 |
| 端口 8000/5173 被占用 | 有残留进程 | `netstat -ano | findstr :8000` 找到 PID 后结束 |
| 保存为 ft 结果报错 | 未先运行批量评测 | 先点"运行批量评测"，完成后才能保存 |

# 立项书 · GeneralGameAgent-Web（延伸项目）

> 性质：课后延伸项目（非课程评分项），独立仓库、独立版本。
> 前身：课程课题七"通用游戏智能体"（`../GeneralGameAgent/`，已结课）。
> 启动：2026-08-21 | 组队：独立完成

---

## 1. 课题概述与背景

**课题名称**：NitroGen 领域适配微调（rocket_league）与可视化前端

**背景（为什么做）**：课程项目完成了 NitroGen 模型的离线评测体系，但 **M4 摇杆相关系数未达标**（baseline -0.1，要求 ≥0.4）。归因结论（G11）为"无条件 zero-shot 模型能力上限"——模型没有任何 game conditioning，摇杆预测与人类操作无相关。本延伸项目目标是：**通过 LoRA 微调让模型真正适配 rocket_league，把 M4 指标拉到达标线，并做 Web 前端展示微调前后对比**。

**一句话目标**：自研 LoRA 微调管线适配 rocket_league → 微调后 M4 达标（摇杆相关系数 ≥0.4）→ 前端交互展示"微调前/后"对比。

**前置事实（已查证，不重复踩坑）**：
1. NitroGen 官方仓库**无训练代码**（`flow_matching_transformer/` 仅 modules.py + nitrogen.py），README 声明"可通过 post-training 适配未见游戏"但脚本需自研；
2. 模型为 500M 参数 DiT，输入单帧 → 输出动作块（实测 18 步）；
3. 训练数据现成：统计集 38400 帧（chunk_0000~0031）+ 测试集 3600 帧（chunk_0032~0034，与课程评测口径一致）；
4. LoRA 在 8G 显存可行：冻结视觉编码器与主干，仅训练 attention 低秩矩阵（~2~5% 参数）；
5. 帧号↔标注对齐规则已验证：`帧号 = chunk_id × 1200 + 行号`（课程 T1 结论）。

## 2. 执行顺序（三阶段 + 一个前置验证）

```
阶段 0（半天）: 微调可行性 spike——跑通 1 个训练 step，loss 可算且下降
阶段 1（前端 v1）: 查看器 + 仪表盘，接入 baseline 结果，后端 API 多版本化
阶段 2（LoRA 微调）: 正式训练（数小时）→ 测试集评测 → ft 结果入库
阶段 3（前端 v2）: 微调前后对比视图（指标/曲线），时间够则补批量推理
```

> 顺序依据：前端 v1 先出可见成果验证技术栈；阶段 0 与阶段 1 **并行**——微调是最大不确定项（训练循环 bug/显存/收敛），先花半天验证"能训"，前端 v1 做完时微调可行性已有结论。

## 3. 必做

| # | 条目 | 关键指标 |
|---|------|---------|
| F1 | **LoRA 微调管线**（自研）：行为克隆 + flow matching loss，统计集训练，测试集隔离 | 训练 loss 下降；单 step 显存 ≤8G |
| F2 | **微调后 M4 评测**：复用课程评测口径（按键准确率、触发召回率、摇杆相关系数） | **摇杆相关系数 ≥0.4**，按键召回率较 baseline 提升 |
| F3 | **后端 API**（FastAPI）：结果集多版本化（`baseline` / `ft`），提供 segments/metrics/figures 接口 | `GET /api/metrics?version=baseline|ft` 返回 JSON |
| F4 | **前端 v1**（Vue3 + Vite + ECharts）：交互查看器（曲线筛选/缩放/差异帧）+ 演示仪表盘（指标卡片） | 能加载 baseline 数据并交互 |
| F5 | **前端 v2**：微调前后对比视图（指标并排 + 曲线叠加） | 选择器切 baseline/ft，曲线可叠加对比 |

## 4. 不做（明确排除）

1. **全参微调**：8G 显存不足，仅 LoRA；
2. **其他游戏泛化**：只适配 rocket_league；
3. **实时游戏接入 / 实机演示**：延续课程决策（模型无端到端能力，演示以离线对比为准）；
4. **从零训练新模型**：只在 ng.pt 上做 LoRA 增量；
5. **修改官方 NitroGen 仓库**：只读引用（依赖其模块）；
6. **真机手柄注入 / 虚拟手柄**。

## 5. 主路径与验收（Given-When-Then）

**主路径**：抽帧（复用对齐规则）→ 数据管线 → LoRA 训练循环（flow matching loss）→ 保存 ft 权重 → 测试集评测 → 结果入库（JSON）→ 前端对比展示。

**验收说明**：

1. **微调可跑**：给定统计集 38400 帧与 ng.pt 权重；当运行训练脚本（LoRA 冻结主干，batch 适配 8G）；则 1 个 step 内 loss 为有限值且下降，显存占用 <8G。
2. **微调生效**：给定测试集 3600 帧（与训练隔离）；当运行评测脚本对比 baseline 与 ft；则摇杆相关系数 ft ≥0.4（baseline -0.1），按键召回率提升 ≥2 倍，结果写入 `results/ft_metrics.json`。
3. **前端可用**：给定后端已启动（`/api/results` 返回 baseline+ft）；当打开前端选择器切到 ft；则指标卡片更新为 ft 数值、曲线叠加显示微调前后差异，差异最大 5 帧可交互查看。
4. **数据一致**：给定同一评测运行两次；当分别请求 `/api/metrics?version=ft`；则两次返回 JSON 结构一致、数值可复现（±随机性容差）。

## 6. 风险与应对

| # | 风险 | 影响 | 应对 |
|---|------|------|------|
| R1 | **自研训练循环与模型接口不匹配**（flow matching forward 语义未知） | 阶段 0 卡死 | 先读透 `nitrogen.py` 的 `get_action`/forward；spike 阶段只求"loss 能算出来"；读不懂就手算梯度核对 |
| R2 | **8G 显存 LoRA 训练 OOM** | F1 失败 | 冻结视觉编码器 + 主干只训 attention；降 batch（1→4 梯度累积）；最坏降到 fp16 微调单层 |
| R3 | **训练不收敛 / 指标不提升** | F2 失败 | 检查 loss 曲线与学习率；换 LoRA 秩/只训最后若干层；**兜底：如实报告 ft 与 baseline 对比，不修饰** |
| R4 | **前端 v2 返工** | 时间浪费 | API 从 v1 就多版本化（`?version=`），v2 只加视图不加数据格式 |
| R5 | 训练耗时不可控（数小时~十几小时） | 节奏拖慢 | 阶段 0 先定"能训"；正式训练跑后台，期间推进前端 v2 布局 |
| R6 | 抽帧 IO 慢（ffmpeg 逐帧进程） | 训练/评测数据管线慢 | 抽帧缓存（同段不重抽）；decord 批量读帧（若装得上） |

## 7. 节奏规划（课后自由时间，建议 1~2 周）

| 阶段 | 内容 | 预估 |

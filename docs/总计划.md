# 总计划 · GeneralGameAgent-Web

> 配套 `docs/立项书.md`（范围/验收/风险定义），本文是执行分解。
> 目标一句话：**LoRA 微调 rocket_league 让 M4 达标（摇杆相关 -0.1→≥0.4）+ 前端展示微调前后对比**。

---

## 0. 里程碑总览

| 里程碑 | 完成标志 | 预估 |
|--------|---------|------|
| M0 | 阶段 0 spike：1 个训练 step 跑通，loss 下降，显存 <8G | 0.5~1 天 |
| M1 | 阶段 1：后端 API 可用 + 前端 v1 展示 baseline | 2~3 天 |
| M2 | 阶段 2：ft 权重 + 测试集评测达标（摇杆 ≥0.4） | 1~2 天 |
| M3 | 阶段 3：前端 v2 对比视图 + README 收尾 | 1~2 天 |

依赖链：`阶段0 →(可行性)→ 阶段2`；`阶段1 →(前端基础)→ 阶段3`；`阶段2 →(ft 数据)→ 阶段3`。
**阶段 0 与阶段 1 可并行**（互不依赖）。

## 1. 阶段 0 · 微调可行性 spike（M0）

**目标**：用最小代价回答"能不能训"——不是完整训练，只求 1 个 step 的 loss 有限且下降。

| # | 任务 | 输出 |
|---|------|------|
| 0.1 | 读透 `nitrogen.py` 的 forward / `get_action` / 动作编码器语义（模型输入、输出、flow matching 接口） | 接口理解记录（进 `docs/训练接口分析.md`） |
| 0.2 | 数据管线最小版：抽 2 batch（~32 帧）+ 按 `帧号=chunk×1200+行号` 对齐标注 | 最小数据加载器 |
| 0.3 | 训练循环最小版：加载 ng.pt → 前向 → flow matching loss → 反向 → 1 step | spike 脚本 + loss 值 |
| 0.4 | 显存观察：`torch.cuda.max_memory_allocated()` 记录，确认 <8G | 显存记录 |

**验收**（立项书 §5 验收 1）：loss 有限值且 1 step 后下降；显存 <8G。
**砍单**：0.2 用 8 帧即可（只要能出 loss）。
**失败判定**：读不懂 forward 语义 / OOM / loss 为 NaN——则停下来记结论，重新评估（见总风险 R1/R2）。

## 2. 阶段 1 · 后端 + 前端 v1（M1）

**目标**：前端能展示 baseline 结果并交互；后端 API 从第一天多版本化。

### 2.1 后端（FastAPI）

| # | 任务 | 输出 |
|---|------|------|
| 1.1 | 搭 FastAPI 骨架（`backend/main.py` + 依赖） | 可启动服务 |
| 1.2 | **baseline 数据入库**：把课程 `results/`（test_set_metrics.md、21 段 top5、m5 对比表）转结构化 JSON | `results/baseline/`（metrics.json / segments.json） |
| 1.3 | API：`/api/results`、`/api/metrics?version=`、`/api/segments?version=`、`/api/figures/<name>` | 四个端点，多版本参数生效 |
| 1.4 | 指标计算逻辑抽公共库（与课程 evaluate.py 共享口径：按键准确率/触发召回率/F1/摇杆相关） | `backend/metrics_lib.py` |

### 2.2 前端（Vue3 + Vite + ECharts）

| # | 任务 | 输出 |
|---|------|------|
| 1.5 | Vite 脚手架 + Vue3 工程化（路由/组件结构） | 可 `npm run dev` |
| 1.6 | **演示仪表盘**：指标卡片（baseline 的 M4 四指标 + 判定） | 仪表盘页 |
| 1.7 | **交互查看器**：21 段曲线列表 + ECharts 曲线（缩放/筛选）+ 差异帧标注 | 查看器页 |
| 1.8 | 页面布局/导航 + 响应式 | 完整 v1 |

**验收**（立项书 §5 验收 3 的 baseline 部分）：打开前端能看到指标卡 + 曲线交互；`/api/metrics?version=baseline` 返回 JSON。
**砍单**：1.7 降级为"只读静态图 + 图例说明"；1.8 简化为单页。

## 3. 阶段 2 · LoRA 微调 + 评测（M2）

**目标**：正式训练出 ft 权重，测试集评测达标。

| # | 任务 | 输出 |
|---|------|------|
| 2.1 | 数据管线完整版：统计集 38400 帧抽帧**缓存**（不重抽）+ 标注对齐 + 训练/验证 split | `train/data_pipeline.py` + `data/` 缓存 |
| 2.2 | LoRA 实现：优先 peft（若适配自定义模型），否则手写 attention 低秩旁路 | `train/lora.py` |
| 2.3 | 训练循环：flow matching loss（MSE 速度场）+ AdamW + 学习率调度 + 梯度累积（batch=1×N 防 OOM） | `train/train_lora.py` |
| 2.4 | 正式训练（后台数小时）→ 保存 ft 权重 | `train/checkpoints/ft_lora.pt` |
| 2.5 | 评测：测试集 3600 帧，baseline vs ft 对比（复用 metrics_lib 口径） | `results/ft/metrics.json` + 对比表 |
| 2.6 | ft 结果入库 + 曲线段数据（供前端 v2） | `results/ft/segments.json` |

**验收**（立项书 §5 验收 2）：测试集摇杆相关 ft ≥0.4；按键召回率 ≥2 倍提升；结果写 JSON。
**失败预案**（总风险 R3）：指标不达标 → 调 LoRA 秩/层/学习率重试一次；仍不达标 → **如实对比呈现**，前端照做（v2 展示"提升失败"也是结论），不修饰。

**目标**：微调前后对比视图 + 项目收尾。

| # | 任务 | 输出 |
|---|------|------|

| 3.5 | 可选：批量推理加速（立项书 A 方案，若时间够） | 加速版评测 |

**验收**（立项书 §5 验收 3 完整版）：切到 ft → 指标卡更新、曲线叠加显示差异。
**砍单**：3.5 随时可砍；3.3 降级为"指标并排无叠加"。

## 5. 风险总表（执行视角）

| 风险 | 阶段 | 应对 | 状态 |
|------|------|------|------|
| R1 训练接口/forward 语义读不懂 | 0 | spike 只求 loss 能算；手算梯度核对；读不懂记结论停 | 未触发 |
| R2 8G 显存 OOM | 0/2 | 冻结视觉编码器+主干；batch=1 梯度累积；fp16 | 未触发 |
| R3 训练不收敛/指标不达标 | 2 | 调秩/层/学习率一次；仍不达标如实对比呈现 | 未触发 |
| R4 前端 v2 返工 | 1→3 | API 多版本化从 v1 就做（F3 已固化为必做） | 已规避 |
| R5 训练耗时不可控 | 2 | 后台跑；期间推进前端 v2 布局 | 未触发 |
| R6 抽帧慢 | 0/2 | 抽帧缓存；decord 批量读帧（可选） | 未触发 |
| R7 peft 不适配自定义模型 | 2 | 手写 LoRA（attention 低秩旁路，~100 行） | 未触发 |

## 6. 砍单总顺序（时间不够时）

1. 3.5 批量推理（可选）→ 2. 1.7 查看器交互降级 → 3. 3.3 曲线叠加降级 → 4. 1.8 响应式
2. **不可砍**：0.x（可行性）、2.x（微调核心）、1.6 仪表盘、3.2 指标对比、3.4 收尾

- 排错按五项（现象/期望/日志/文件/已尝试）记录到 `docs/排错记录.md`；
- 阶段结束核对里程碑（M0~M3）。

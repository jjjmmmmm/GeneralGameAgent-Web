# 计划 · 摇杆加权 loss 重训 ft（B 方案）

> ⚠️ **已验证失败，方向放弃（2026-08-24）**：w4/w8 训练集摇杆相关未抬头；测试集 `jw_w8` 相关 +0.113 ≈ 旧 ft +0.126 无提升，且触发召回率 65.75%→15.25% 大幅回退。数值验证确认加权机制生效，但摇杆相关指标（单帧 2 点 Pearson）噪声过大，可提升信号被淹没。**结论：摇杆相关不达标确认为 LoRA 行为克隆 + flow matching 的能力边界，如实呈现。** 代码已回退，`jw_w4.pt`/`jw_w8.pt` 保留本地（不入仓），项目仍用旧 `ft_lora.pt`。

> 2026-08-24 制定 · 目标：冲击摇杆相关系数 ≥0.4（当前旧 ft +0.126，唯一未达标指标）

## 0. 背景与诊断结论（为什么是 B 不是 A）

用 `train/diagnose_train_set.py` 测现有权重在**训练集**（chunk 0000~0031，模型见过的帧）上的摇杆相关：

| 权重 | 训练集 jl_corr | 测试集 jl_corr |
|------|---------------|---------------|
| baseline | -0.041 | -0.111 |
| 旧 ft | **+0.042** | +0.126 |

**结论**：ft 在训练过的帧上摇杆相关仅 +0.042（与测试集同量级）→ 模型**没学会**"画面→摇杆"映射，不是泛化差。根因 = flow matching loss 对 25 维等权，摇杆只占 4/25=16%，梯度被按钮主导。

**推论**：扩数据（A 方案）对摇杆无效（连见过的帧都学不会），方向已放弃；必须让摇杆梯度放大 → **摇杆加权 loss（B 方案）**。

## 1. 技术方案（不改 NitroGen 源码）

**加权落点**：`NitroGen/nitrogen/flow_matching_transformer/nitrogen.py` forward 内：

```python
mask = data["actions_mask"]                      # 训练时由 tokenizer.encode 生成，全 True
raw_loss = F.mse_loss(pred_actions, velocity, reduction="none")   # (B,18,25)
mask = has_real_action[:, None, None] * mask
raw_loss = raw_loss * mask
action_loss = (...).sum() / (mask.sum() + 1e-6)  # 归一化用 mask.sum()
```

**加权手段（关键）**：`mask` 直接来自数据可控的 `data["actions_mask"]`，且归一化分母是 `mask.sum()`。因此**把 `actions_mask` 从全 1 换成 float 权重矩阵（21 个按钮列 = 1，4 个摇杆列 j_left/j_right = w）**，即可让摇杆维度梯度相对放大 w 倍，而按钮不变。归一化 `Σw` 不抵消相对权重（梯度 dloss/dpred_j ∝ w_j / Σw）。

**改动点（全部在 `train/train_lora.py`）**：
- `encode_sample()` 返回后，将 `out["actions_mask"]` 替换为权重张量：`torch.ones(1,18,25)`，再把 `[..., 21:25]`（摇杆列，layout = 21 按钮 + j_left 2 + j_right 2）设为 `--j_weight`
- 新增 CLI 参数 `--j_weight`（默认 1 = 等权，不影响旧行为）

## 3. 验收（Given-When-Then）

- **给定**：`train_lora.py` 支持 `--j_weight`，诊断脚本就绪；
- **当**：以选定 `--j_weight`（4~8）重训 ft 并用 Z1r1S--MJS4 测试集（chunk 32~34）评测；
- **则**：① 新 ft 训练集摇杆相关较旧 ft(+0.042) 明显抬头（"学会了"）；② 测试集摇杆相关 ≥ +0.126 且目标 ≥0.4；③ 按键准确率不显著回退（≥88%，不因加权牺牲）；④ 结果如实记录到 `train/RESULTS.md`。

## 4. 风险与回退

| 风险 | 应对 |
|------|------|
| 权重过大 → 按键指标回退 | w 从 4 起递增，监控按键准确率；优先保按键不显著回退 |
| 加权后仍不达标 | 如实呈现；可试 w=12~16 或"摇杆专用 loss 组件"（下一步再说） |
| flow matching 时间采样随机性 | 评测沿用 K=3 多数票口径；摇杆波动可多跑一次取均值 |
| 训练耗时 | 快速验证先跑 400 步（~30 分钟）看信号，信号确认再跑正式训练 |
